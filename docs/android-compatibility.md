# Android 适配与验证

## ACC 1.7 与无 root 1.4

两个版本都使用 Android 17 SDK 37.2、Build Tools 37.0.0 和目标 API 37。ACC 版支持 Android 6.0（API 23）及以上，无 root 版支持 Android 7.0（API 24）及以上。更新沿用各自原有的包名和签名，旧版的阈值与等待阶段随覆盖升级保留。

| 环境与方法 | 本轮实际验证 |
| --- | --- |
| Android 6.0，API 23 官方 ARM64 模拟器 | 安装正式 ACC 版，在仪表盘与充电控制间切换。趋势页在旋转和进程回收后恢复。通过系统文件选择器导出内置 ACC 模块，拉回的 ZIP 与固定上游版本逐字节一致。滑杆无障碍节点读回真实温度和范围。 |
| Android 7.0，API 24 官方 ARM64 模拟器 | 无 root 版安装、传统前台通知、开始和停止记录、75% 到 62% 再到 50%、预约、历史与用量报告。官方 Shizuku 经电脑启动并授权，实际读到 UID 2000 的电池诊断。模拟器没有可写停充节点。 |
| Android 7.0、8.0、17.2 驱动身份校验 | 重新创建同名目录后，记录到的文件系统设备号和 inode 随实际节点改变，可识别旧归属。Android 7 使用平台 Os.stat，Android 8 及以上保留原有文件身份格式。 |
| Android 17.2 稳定版，16 KB 页 | 使用真实通知设置分别关闭单个提醒渠道、撤销整个应用通知，再从应用内入口返回对应设置。320dp 小横屏、200% 字号下完成预约和取消。切换字号及深色模式后保留输入草稿。系统无障碍节点提供阈值与服务器输入的标签、标题和趋势摘要。 |
| Android 17.2 真实服务与模拟电池 HAL | 覆盖升级后 62% 仍等候回落。温度正常且到 50% 时，系统上报过压仍对自动化返回暂停。进程重开后遇到未知健康读数仍保持保护，系统报告正常才放行。还验证了过热、失效、通用故障、临时补电、无电池以及重新插入电池时的策略。 |
| 可控 ACC 读数与驱动目录 | ACC 版读回 15/45°C 并正确显示；遇到 15/58°C，保留现值，主动选择有效预设后才能提交。无 root 版识别 BAT0 与有明确系统标记的其他电池，排除鼠标电池，多电池归属不确定时提示。有效闰日、无效日期及未上报日期分别测试。 |

两份签名 APK 还在 Android Canary 镜像 ZP11.261016.008（16 KB 页）完成覆盖安装、默认竖屏和双倍字号横屏的启动检查。平板、旋转和窄窗的结果不能单独证明跨物理中缝的显示效果。

在专用模拟器上可运行下方的界面检查。另可启动无 root 版记录，使用 50%–75% 并在「连接本机自动化应用」中选择 `com.android.shell`，再运行 `python3 tests/health-policy-smoke.py emulator-5554`。该回归通过模拟器电池接口改变电量、电源与健康状态，从应用提供给外部接收方的真实接口验证输出。测试会推进该模拟器中保存的养护阶段，结束时恢复模拟电池属性。

已有产品、系统 API、适用机型与实物验证条件见[跨产品能力复核](capability-review.md)。

## 上一发布的基线

归根 ACC 1.6 和无 root 1.3 使用 Android 17 SDK 37.2、Build Tools 37.0.0 构建，目标 API 为 37，最低安装 API 为 26（Android 8.0）。两个版本分别沿用原包名及签名。两份 APK 都没有随应用进程加载的原生共享库。[Android 17 行为变更](https://developer.android.com/about/versions/17/behavior-changes-17) · [Android 16 KB 内存页](https://developer.android.com/guide/practices/page-sizes)

### ACC 1.6 与无 root 1.3 的验证范围

| 运行环境 | 已验证的行为 |
| --- | --- |
| Android 8.0（API 26） | ACC 1.5、无 root 1.2 分别覆盖升级；两版首页在竖屏和横屏双倍字号下均可见。 |
| Android 11（API 30） | 320dp 窄屏、深色、200% 字体、横屏表单和大屏；无 root 版旋转保留阈值输入，小组件在 160×88dp 和 600×300dp 分别显示紧凑和完整内容。ACC 版的小横屏对话框可滚动到全部操作。 |

## 可复现的界面检查

在专用模拟器安装同一版本的两个安装包，解锁屏幕后，从仓库根目录运行以下命令，将序列号换为该模拟器的实际值。

```sh
python3 tests/display-smoke.py emulator-5554 --screenshots /tmp/rootward-display
```

脚本分别用竖屏默认字号和横屏双倍字号启动两个版本，核对界面树中的可见文字，按需保存系统截图，完成后恢复原有字号和旋转设置。截图可用于检查状态栏、导航栏、留白和换行。设置页、表单、桌面组件及实际充电状态另有专项检查。

## 权限与硬件

- 记录和温度提醒由用户开启的前台服务提供。Android 13 及以上允许单独关闭通知；没有通知权限时，系统提醒的可见性受限。
- Android 17 访问局域网 Home Assistant 服务器时，在插座对话框中申请「附近的设备」权限。公网 HTTPS 服务可直接连接。系统信任的证书和可访问的服务器仍是前提。[Android 局域网权限](https://developer.android.com/privacy-and-security/local-network-permission)
- 真正的电池停充分别依赖获得授权的 ACC 驱动、允许 shell 写入的内核接口或外接智能插座。模拟器可验证界面和策略；厂商系统后台限制、物理插座通断和电芯电流需在相应设备验证。

两份 APK 均已校验原更新签名和 16 KB ZIP 对齐。另以 Android Lint 检查版本受限的 API、内联常量和资源类型，并运行无 root 版的策略测试及 ACC 版的配置读回、跨插拔巡航回归测试。
